## 实现与边界

- Python `CalendarService`统一财报、宏观、央行事件的来源、股票关联、预告/发生/更新时刻、精度、时区及读取状态。
  复用同一个`CapabilityRegistry`、`ProviderService.query`、提供商配置/凭证和已有只读适配器；没有另建连接健康状态或数据访问实现。
- `calendar.earnings`、`calendar.macro`由`research.events`可用性派生；真实央行覆盖明确`NOT_IMPLEMENTED`。
  Massive现有能力不包含事件；不可用不查询、不展示模拟回退。能力目录展示同一状态，三个新能力均不暴露为Agent工具。
- 六条自造固定事件涵盖三个类别，参考时刻固定`2024-01-16T21:00:00Z`。
  Apple、港股财报、Tesla、PCE、已发生宏观、FOMC均为合成示例，不是真实安排或投资依据。
  两个重复来源记录合并后仍是六个事件；实际获取时间独立记录。详情见[来源记录](SOURCES-step20.json)。
- 只转换来源提供的明确时刻。来源只有日期/盘前/盘后时保留当地日期，不编造小时或用日锚点充当财报时刻。
  无时区的本地时间、DST重复/不存在时刻、时区与偏移不符均标缺口；只在偏移或有效IANA时区明确时转换。
  窗口按所选显示时区的日期含首尾过滤，最大90天；日期精度的事件保留来源当地日，不假称已完成精确跨区换算。
- 预告经过显示“经过但未确认发生”；只有来源声明发生或提供发生时刻才显示对应来源状态，不由查询时钟推断发生。
  来源提供未来发生时刻则标冲突、时间关系未知，并禁止研究跳转。关联来源不证明投资影响。
- 同一来源ID在同一模式/提供商/类别生成稳定身份；无ID按实际内容、股票和源时刻识别。
  有明确更新时刻的修订保留较新版本；同一身份且无法排序的冲突可见、禁止研究。新快照追加保存，旧快照不覆盖。
- `0015_calendar`只新增`calendar_snapshots`；每份快照保存查询、实际能力读取、原始结果、哈希、JSON Pointer、事件及缺口。
  切时区、读历史、重启不重新查询；请求UUID重复返回原快照，不同内容复用UUID报冲突。
  原始事实只能凭快照/读取UUID获取，校验哈希；不接受磁盘路径。异常、结果模式/来源不符保存为安全失败。
- 五个命名桌面操作使用来源验证、字段白名单和启动令牌，类型由Python/OpenAPI生成。
  事件页沿用已有桌面风格，增加类别/日期/时区选择、显式刷新、来源与缺口、原始事实和快照历史。
  迟到来源/原始事实响应不能覆盖新选择；重复刷新不能创建两份快照。
- 跳转研究只填实际股票、数据模式、提供商及快照/事件ID/显示时区，默认选择已有`event-driven`策略。
  Python重新校验股票关联和证据，冻结上下文到计划；财报查询指定股票，宏观/央行查询不伪造股票关联。
  无来源关联的宏观事件要求用户明确选择研究股票，并标“用户自主选择”。切股票/来源会清除旧事件草稿。
  跳转不自动采集或消费模型；显式采集和生成报告沿原流程。研究计划、报告、Markdown及原始事实入口保留同一上下文。
  日历快照不伪装为当前研究执行证据ID，旧研究/报告默认没有事件上下文仍可读取。
