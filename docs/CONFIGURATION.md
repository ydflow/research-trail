# 发布前本机配置与真实验收

按顺序准备：模型 → 真实行情 → 独立干净 Windows。外部追踪可以稍后配置。配置保存、假测试通过、真实请求成功和安装验收分别记录，不能互相替代。本文不包含密钥；不要把 API Key、Access Token、账户号或持仓发到聊天、提交到 Git 或截图公开。

## 1. 打开当前开发版

在 CMD 运行：

```cmd
cd /d D:\folio\research-trail
start-dev.cmd
```

保留命令窗口，等待“后端健康：运行正常”。若提示缺 Bun、uv、Node，先按 README 安装开发工具；安装包验收的干净 Windows 则不要安装这些工具。当前内部安装包不包含后续源码补齐，不能用旧包证明新代码已验收。

## 2. 先配置一个真实模型

1. 在服务商平台登录并申请 API Key，确认账户支持 API、所选模型可用及费用额度；网页聊天账号不等于 API 已开通。
2. 研迹 → **设置与诊断 → 模型设置**。勾选启用，填写 Base URL、模型标识，勾选需要凭证，点击 **保存配置**。
3. 在同一卡片 **新凭证** 输入 API Key，点击 **保存凭证**。密钥存 Windows 凭证管理器，不回显，也不应写进 URL。
4. **测试假连接**只检查本地状态流程。真实验收到 **会话与事件**，创建会话，选择 **运行模型 → OpenAI兼容／真实模型（使用本机配置）**，输入“只回复：连接成功”，点击 **运行真实模型**。
5. 验收成功需运行终态成功且有真实回答。记录服务商、模型名、运行时间和是否成功；失败只报告研迹错误代码，不粘贴密钥或完整私人回复。

如果你选择 DeepSeek，截至本指南核对时官方示例使用：

| 字段 | 填写值 |
| --- | --- |
| Base URL | `https://api.deepseek.com` |
| 模型 | `deepseek-flash`（以你账号当前可用模型为准） |
| 思考级别 | 首次连通选择“关闭思考”；本轮源码新增控件，旧安装包没有 |
| 新凭证 | 你自己的 API Key，只在本机输入 |

“关闭思考”会显式发送该服务商的禁用参数。低/中级别会被当前适配器明确拒绝；高思考及多轮工具调用还需另验，不能用单句成功证明。其他 OpenAI 兼容服务商填写其官方 Chat Completions 源站/模型名；服务商不支持所选参数时不静默降级。

申请入口与当前参数以 [DeepSeek 官方首次调用说明](https://api-docs.deepseek.com/en/) 为准。调用可能产生按量费用；先做一次简短测试，不开启自动付费评测。

## 3. 再配置真实行情

当前研迹 Longbridge SDK 配置要求 **App Key、App Secret、旧版 Access Token** 三项。官方现在也支持 OAuth，但 OAuth access token 不能直接填进本应用的旧版 Access Token 字段。如果平台只给 OAuth，需要先处理适配缺口，不要硬填或声称连接已成功。[Longbridge 官方快速开始](https://open.longbridge.cn/zh-CN/docs/getting-started)

1. 到 Longbridge 开发者中心申请适合你账户的数据访问权限，取得三项凭证；仅验证公开行情无需把个人真实持仓公开。
2. 研迹 → **数据与只读账户**，数据提供商选 **Longbridge 行情**，启用，按服务商账户数据区域选全球/中国，点击 **保存提供商配置**。
3. 在本机填写三项密码输入框，点击 **保存提供商凭证**。不要发到聊天。
4. **只读查询验收**选 **真实查询（需要本机凭证与权限）**，先选 `market.quote`，代码 `AAPL.US`，执行一次真实只读查询；再验 `market.kline` 和新闻。记录代码、来源时间、运输方式、状态/错误代码。
5. 单项成功不证明全部能力可用。`restricted` 是服务实际返回的权限受限；未配置、未请求、超时须分别记录。服务区域和“实时”下拉声明不能授予实时行情权限。

只读账户是独立配置项；如需验收，选 **Longbridge 只读账户** 单独保存配置/凭证，结果只在本机核对。部分能力依赖用户另装并登录官方 CLI，当前安装包未提供它；先完成 SDK 行情，再按实际缺能力处理 CLI。

本轮已在本机保存Longbridge三项凭证并验证AAPL.US报价、5条K线和5条新闻：均为real/sdk、cached=false。全球`.com`端点在本机TLS连接被重置（Windows 10054）；`.cn`可用，配置已改为中国区域，其他配置保留。仅证明本机三项能力，不代表全市场、实时权限或安装包通过。正常关闭并通过`start-dev.cmd`重开研迹，加载较长Access Token与SDK时间兼容修复；旧进程仍使用旧校验器。凭证只在Windows凭证管理器，不在源码或验收记录。新凭证请仅在本机输入。

## 4. 外部追踪可后配

在 **评测中心 → 外部追踪与脱敏预览** 操作。先创建并运行一个离线实验，再分别保存追踪配置、系统凭证，执行 **真实连接检查**。连接检查与数据上传是不同操作。

| 平台 | 需要准备 | 研迹字段 |
| --- | --- | --- |
| LangSmith | 平台 Settings → API Keys 创建 API Key；必要时获取 Workspace UUID | 源站按账户所在区域，默认 GCP US 为 `https://api.smith.langchain.com`；项目 `research-trail`；API Key；单工作区通常 UUID 留空 |
| Langfuse | 项目设置中创建 Public Key / Secret Key | 项目所在区域源站，例如 EU `https://cloud.langfuse.com`；项目标识；两项密钥 |

源站不添加 `/runs`、`/api/public` 或 OTLP 路径，应用负责追加。勾选“允许显式连接和上传”并保存才启用。上传前点击 **生成脱敏预览**，检查仅含案例身份、状态、工具名和断言摘要，再由用户明确勾选确认并上传。默认保持关闭，CI 不连外部服务。

官方配置依据：[LangSmith API Key 与区域说明](https://docs.langchain.com/langsmith/create-account-api-key)、[Langfuse 公共 API 与认证](https://langfuse.com/docs/api-and-data-platform/features/public-api)。

## 5. 准备干净 Windows 环境

优先使用一台未安装研迹开发依赖的独立 Windows 11 x64 电脑，或新安装的 Windows 虚拟机。宿主开发机上隐藏 PATH 的测试已做过，但不等于干净系统验收。

若准备虚拟机：从 [Microsoft 官方 Windows 11 ISO 页面](https://www.microsoft.com/en-us/software-download/windows11) 获取 x64 系统镜像，使用有权使用的 Windows 版本与虚拟化软件；安装前确认虚拟机固件/TPM 满足 Windows 11 要求。现有宿主约 16GB 内存，可先规划客体 6GB 内存、4核、80GB 动态磁盘；这是资源建议，尚未创建或验证。不要为了本项目重装宿主系统或盲目关闭其安全功能。

干净客体内 **不安装 Python、uv、Node、Bun 或项目源码**。先完成系统安装及更新，保存首次验收快照。拿到本轮重新构建、对应源码与 SHA256 的内部候选包后，只复制安装包和验收清单。

逐项验：首次安装 → 不依赖开发工具启动 → 创建模拟会话/研究/离线实验 → 正常退出后所属后端消失 → 重启数据保存且不重发任务 → 备份后数据库升级 → 卸载保留数据 → 重装读回。升级测试还需旧版对应数据库，不能用新空库冒充升级。异常、SmartScreen 和退出残留如实记录。签名证书尚未准备时保留未签名事实，不自行购买。

用户目录、备份与卸载规则见 [WINDOWS-INSTALL.md](WINDOWS-INSTALL.md)。旧内部安装包只能验证旧构建，本轮源码验收、重新打包与干净环境验证仍需完成。

## 回复什么即可继续

先完成模型这一项，回复“已保存模型配置，服务商 __，模型 __；简短真实调用成功/错误代码 __”。不要发送密钥。随后补行情，再准备干净 Windows。即便配置完成，真实模型 A/B、质量量表、概率校准、SDK 分发许可等源码/验收缺口也需继续处理；配置本身不表示已达到 v1.0.0。
